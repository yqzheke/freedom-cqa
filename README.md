# Freedom CQA

Русскоязычное рабочее место аналитика качества. Next.js, TypeScript, Gemini и Supabase. Официальный чек-лист **для чатов** доступен по умолчанию. Для звонков опубликуйте отдельную версию с критериями audio/both. Три стартовых диалога синтетические. Реальные оценки появляются только после запроса к модели.

## Локальный запуск

Node 24, npm. Открыть каталог в VS Code, выполнить `npm ci`, скопировать `.env.example` в `.env.local`, затем `npm run dev -- -H 127.0.0.1`. Открыть http://127.0.0.1:3000. Без ключа работают импорт JSON, редактор и просмотр. В локальном режиме состояние хранится в приватном каталоге .cqa. После аварийного завершения локальной записи при остановленном приложении можно удалить оставшийся .cqa/lock. Не запускайте dev-сервер на внешнем интерфейсе.

## Подключения

В Supabase SQL Editor применить supabase/migrations/001_workspace.sql к выбранному проекту. Задать SUPABASE_URL и SUPABASE_SECRET_KEY только на сервере. Прототип атомарно сохраняет версии, результаты, обращения, решения и журнал затрат одним обновлением JSONB с проверкой ревизии. Начальные синтетические записи материализуются при первой записи. Для масштабирования этого прототипа потребуется разделение состояния на таблицы.

В Vercel импортировать репозиторий как Next.js, задать переменные окружения, включая длинный случайный DEMO_ACCESS_TOKEN. После деплоя открыть адрес с фрагментом /#access=TOKEN. Токен обменивается на восьмичасовой HttpOnly cookie. Не публикуйте ссылку. На Vercel локальное файловое хранилище отключено.

ORGANIZER_API_BASE_URL — полный подписанный адрес GET со страницы 3 руководства с сохранёнными служебными параметрами; group_id устанавливается сервером. В ORGANIZER_AUDIO_ALLOWED_HOSTS укажите точные имена хостов плеера и MP3 через запятую. Импорт не отправляет данные модели. При повторном импорте изменённый диалог получает новую версию.

Задайте GEMINI_API_KEY и доступные вашему проекту GEMINI_TEXT_MODEL и GEMINI_AUDIO_MODEL. Сервер вызывает Google generateContent с JSON-схемой для текста и inlineData для аудио. Для каждого model ID заполните MODEL_PRICES_JSON объектом с input, cached, output, audio (USD за миллион токенов) и датой проверки. Сверьте актуальные тарифы в своём аккаунте. EVALUATION_BUDGET_USD задаёт суммарный лимит резервов, MAX_CALL_USD — резерв одного вызова. Отдельно настройте лимиты в аккаунте провайдера. Точная стоимость заранее неизвестна. При отсутствии usage резерв сохраняется. Незавершённый вызов может быть оплачен. Повтор требует явного действия.

## Контрольная группа и оценка точности

В час 23 введите выданный group_id в разделе импорта. Сверьте количество, выберите версию, начните с одного диалога. Очередь обрабатывается последовательно, короткая пакетная команда запускает до трёх. Оставьте вкладку открытой. Сетевой сбой требует проверки журнала расходов перед повтором. В час 24 сохраните SHA и ID деплоя. Пересчёт по новой версии выполняется из интерфейса.
Для независимого сравнения с эталоном используйте `node scripts/compare.mjs ground-truth.json predictions.json`. Формат обоих файлов — массив объектов с conversation_id, score и answers (словарь ID критерия → boolean, число или строка N/A). Отчёт показывает среднюю абсолютную ошибку итогов, покрытие и совпадения по критериям. Ground Truth не входит в поставку.

## Проверка

npm run lint, npm run typecheck, npm test, npm run build, npm run e2e. Для браузерных тестов требуется Edge. E2E использует отдельное временное состояние и тестовый сохранённый результат для проверки пересмотра. Он не измеряет качество модели. Ведите отдельную ручную сверку RU/KZ/EN.

## Демонстрация (5 минут)

- 0–1: отфильтровать набор и открыть диалог.
- 1–3: показать версию, шкалу, N/A, взвешенный итог, переход из доказательства к реплике. В звонке открыть запись и объяснить ограничения атрибуции.
- 3–4: подать апелляцию, перейти в режим рассмотрения, изменить ответ с причиной, сравнить исходный и итоговый балл.
- 4–5: заменить произвольный критерий, опубликовать версию и запустить оценку нового диалога. В журнале показать модель и стоимость.

## Границы прототипа

В официальном чат-чек-листе акустических критериев нет. Для отдельного голосового чек-листа запись передаётся аудиомодели, а затем наблюдения используются текстовой моделью. До ручной проверки временные метки приблизительные. Поддерживаются WAV/MP3 до 4 МБ, в том числе HTML-плеер организатора с MP3 source. Пять DEV-файлов при проверке укладывались в лимит. Крупные записи требуют предварительной подготовки. Проверяйте новые источники, качество атрибуции и реальные расходы до группового запуска. Прототип не подтверждает раздельную идентичность проверяющего и заявителя.
