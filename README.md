# Aegis · Freedom CQA

Рабочее место для оценки качества диалогов: настраиваемый чек-лист, доказательства, расчёт баллов и апелляции. Прототип для хакатона Freedom Broker. Интерфейс на русском; входные диалоги могут быть RU, KZ и EN.

## Что реализовано

- Список диалогов, фильтры, карточка с перепиской и оценкой, переход к реплике-доказательству.
- Восемь критериев официального чек-листа чатов; отдельная версия для звонков. Редактор критериев, весов, шкал и N/A с публикацией версий.
- Проверка структуры ответа модели, шкал, допустимости N/A, ссылок и точных цитат до расчёта результата. При отсутствии действия показывается проверенный диапазон и объяснение.
- Взвешенный итог с перераспределением весов при N/A и округлением half-up до двух знаков. Грубая ошибка отмечается отдельно и не обнуляет итог автоматически. Неполная оценка не выдаётся за числовой результат.
- Апелляция по критерию, решение человека с причиной, сохранение исходной оценки и пересчёт. Отдельная AI-переоценка не отменяет зафиксированное решение человека; предложения по остальным критериям применяются после подтверждения.
- Рекомендации оператору со ссылками на основания. Они не меняют баллы и не вызывают модель.
- Очередь, история попыток и этапов, ограничение запросов, диагностика ошибок без полных ответов провайдера.
- Импорт набора организаторов, групповые запуски по версии чек-листа, официальный экспорт results.json.
- Симулятор весов: сравнение старого и возможного итога на проверенных сохранённых оценках без API-вызовов и изменения официальных результатов.
- Прослушивание звонка и версии ручных исправлений транскрипта с сохранением оригинала. Групповые оценки и официальный экспорт используют оригинал.

## Быстрый локальный запуск

Требуются Node.js 24 и npm. Из корня репозитория:

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local`, не перезаписывая существующий файл. В PowerShell:

```powershell
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm run dev -- -H 127.0.0.1
```

Откройте адрес из терминала, обычно http://127.0.0.1:3000. Без API-ключей доступны просмотр, редактор и импорт; новая AI-оценка требует провайдера. Не открывайте dev-сервер на внешнем интерфейсе.

Локальное состояние сохраняется в `.cqa/`. Не удаляйте его для сброса лимитов. Перед очисткой истории сделайте резервную копию; не удаляйте lock-файл при работающем процессе.

## Провайдеры и конфигурация

Шаблон `.env.example` оставляет Gemini провайдером по умолчанию. Для текстового сценария Groq с GPT-OSS задайте явно:

```dotenv
TEXT_EVALUATION_PROVIDER=groq
GROQ_API_KEY=
GROQ_TEXT_MODEL=openai/gpt-oss-120b
GROQ_FREE_REQUESTS_PER_DAY=3
EVALUATION_BUDGET_USD=0
MAX_CALL_USD=0
```

Ключ внесите только локально. Перезапустите сервер после изменения настроек. Лимит 3 здесь пример для осторожного теста, не обещание достаточной квоты. Проверяйте тариф и доступную квоту в своей организации. Код также поддерживает `qwen/qwen3.8-27b`; автоматической смены модели или провайдера нет. Модель фиксируется для запуска и его повторов.

Groq читает ключ непосредственно из серверного файла `.env.local`. Текущая реализация не поддерживает обычное облачное развёртывание Groq только через переменные Vercel без дополнительной доработки.

Gemini используется для звонков и может быть выбран для текста. Настройки: `GEMINI_API_KEY`, `GEMINI_TEXT_MODEL`, `GEMINI_AUDIO_MODEL`. Для существующего режима `free_only` требуются `GEMINI_BILLING_MODE=free_only`, `GEMINI_FREE_MODEL=gemini-3.5-flash`, соответствующая модель, положительный целочисленный `GEMINI_FREE_REQUESTS_PER_DAY` и оба долларовых лимита 0. Наличие имени модели в коде не доказывает её доступность или бесплатность для вашего аккаунта.

Обычный бюджетный режим Gemini требует актуальных цен в `MODEL_PRICES_JSON` и достаточных положительных резервов `MAX_CALL_USD` / `EVALUATION_BUDGET_USD`. Цены в шаблоне не считайте проверенным текущим тарифом. Приложение не проверяет биллинг аккаунта; денежные настройки приложения не заменяют ограничения у провайдера.

### Квоты и очередь

Дневной лимит приложения считается по UTC и включает фактические попытки, ошибки и repair. Один диалог может потребовать два вызова. Увеличение локального лимита не увеличивает квоту провайдера.

Groq резервирует окно 8 000 токенов / 65 секунд на каждый вызов, включая repair. Если фактическое потребление выше, ожидание продлевается. Это консервативное ограничение, а не точный прогноз стоимости. Ожидание оставляет задание в очереди и продолжается автоматически, **пока вкладка приложения открыта**. До отправки ожидание не расходует попытку. HTTP 429 приостанавливает очередь; возобновление вручную после указанного ожидания. Вызовы из других приложений и большой отдельный запрос могут исчерпать квоту несмотря на локальную защиту.

## Данные и приватность

- Ключи остаются на сервере. `.env.local`, локальное состояние и тестовые каталоги исключены из Git. Не публикуйте исходные диалоги, аудиоссылки и журналы с персональными данными.
- Free-режимы разрешают встроенные синтетические примеры. Дополнительно есть узкое разрешение на **60 исходных синтетических чатов конкретного DEV-импорта**, только Groq / `openai/gpt-oss-120b`. Проверяются хеш импорта и точное содержимое каждого диалога.
- Это разрешение не распространяется на реальные звонки, PROD, изменённые транскрипты, другой импорт, модель или провайдер. Полный DEV-запуск с пятью звонками блокируется целиком, если хотя бы одна запись не разрешена.
- Zero Data Retention настраивается в организации провайдера, не приложением. Его наличие не заменяет разрешение на передачу данных. Groq может сохранять служебные метаданные.
- Диагностика показывает этап, статус HTTP и безопасный код ошибки. Она не публикует ключи, полный диалог или тело ответа модели.

## Импорт и официальная сдача

`ORGANIZER_API_BASE_URL` задаёт выданный организаторами GET endpoint с его служебными параметрами; группа передаётся приложением. `ORGANIZER_AUDIO_ALLOWED_HOSTS` содержит разрешённые имена хостов аудио через запятую. Произвольные адреса для загрузки аудио не разрешены.

Во вкладке **Запуски → Официальная сдача: results.json** выберите набор, версию, команду Aegis и источник оценок: исходный AI или подтверждённые текущие решения. Экспорт выбирает результаты текущей текстовой модели, как и контрольная группа. DEV содержит ровно 65 записей, PROD ровно 10. Недостающие или ошибочные оценки экспортируются как ошибки, а не выдуманные баллы.

Официальные пути: `results/dev/results.json` и `results/prod/results.json`. Скачивание или локальное сохранение не отправляет работу организаторам и не выполняет commit/push. Диагностический экспорт контрольной группы не заменяет официальный формат. Детали схемы и порядок проверки: [SUBMISSION.md](SUBMISSION.md).

Полная обработка DEV, итоговые файлы сдачи и точность относительно эталонов организаторов не подтверждены этой документацией. Перед сдачей проверьте полноту, ошибки, выбранную версию и модель в фактических файлах.

## Хранение и облако

По умолчанию используется локальное файловое хранилище. Для Supabase примените `supabase/migrations/001_workspace.sql` в выбранном проекте и задайте серверные `SUPABASE_URL` и `SUPABASE_SECRET_KEY`. Состояние прототипа сохраняется в JSONB с контролем ревизии; это не готовая многопользовательская производственная архитектура.

На Vercel локальное хранилище отключено, нужен Supabase. Для доступа предусмотрен `DEMO_ACCESS_TOKEN`: первое открытие с фрагментом `/#access=TOKEN` устанавливает HttpOnly cookie. Ссылку с токеном не публикуйте. Раздельные права проверяющего и заявителя не реализованы. Успешное облачное развёртывание не заявляется; ограничения Groq описаны выше.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run e2e
```

E2E использует установленный Microsoft Edge, отдельный временный каталог состояния и production-сервер на 127.0.0.1:3376 после сборки. Тестовые оценки и подмена сети не подтверждают качество живой модели.

Для независимых эталонов есть `node scripts/compare.mjs truth.json predictions.json`. Входы этого скрипта: массивы объектов с `conversation_id`, `score`, `answers`; это не схема официального results.json. Эталоны в репозиторий не входят.

## Ограничения и демонстрация

Это проверяемый прототип, не сертифицированная система контроля персонала. Валидная цитата не гарантирует правильную интерпретацию модели. Спорные шкалы и ответы требуют проверки человеком. Встроенного ASR нет; точность транскрипта и временных меток должна проверяться отдельно. Прототип не обещает точность на новых эталонах или бесперебойную бесплатную квоту.

Сценарий защиты на 5 минут: [PITCH_RU.md](PITCH_RU.md). На демонстрации явно отличайте сохранённую оценку от нового живого вызова. Не выдавайте ошибки, демонстрационные данные или симуляцию за успешную обработку контрольного набора.
